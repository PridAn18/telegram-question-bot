Общая архитектура

Проект представляет собой один Python-процесс на aiogram 3.x, работающий через Long Polling. Внешние сервисы отсутствуют, кроме Telegram Bot API. Используется встроенная база данных SQLite. Docker, PostgreSQL, Redis, Nginx, веб-сервер, домен и HTTPS не используются. Бот рассчитан на работу как systemd-сервис с автоматическим запуском после перезагрузки VPS.

База данных

Используется SQLite с четырьмя таблицами.

categories
id INTEGER PRIMARY KEY
name TEXT UNIQUE
questions
id INTEGER PRIMARY KEY
category_id INTEGER
question TEXT
answer TEXT
is_active INTEGER DEFAULT 1

UNIQUE(category_id, question)
users
user_id INTEGER PRIMARY KEY
username TEXT
first_name TEXT
selected_category INTEGER
created_at DATETIME
last_activity DATETIME

user_id — Telegram ID пользователя.

user_progress
user_id INTEGER
question_id INTEGER
shown_at DATETIME

PRIMARY KEY(user_id, question_id)

Таблица содержит только уже показанные вопросы.

Алгоритм выдачи вопросов

При первом запуске пользователь автоматически добавляется в таблицу users.

При нажатии «Начать» бот выбирает случайный активный вопрос, которого нет в user_progress данного пользователя.

Показывается только вопрос.

После получения любого сообщения пользователя бот отправляет заранее сохранённый ответ без проверки правильности.

Под ответом отображается кнопка «Далее».

После нажатия кнопки вопрос считается пройденным и записывается в user_progress.

Следующий вопрос снова выбирается случайным образом среди ещё не просмотренных.

Если количество просмотренных вопросов равно количеству активных вопросов выбранной категории, выполняется очистка записей пользователя из user_progress, после чего начинается новый случайный цикл.

Автоматическая установка

Проект должен быть полностью готов к деплою без редактирования файлов на VPS.

После публикации на GitHub установка должна сводиться к запуску install.sh, который:

устанавливает необходимые системные пакеты (если отсутствуют);
клонирует репозиторий;
создаёт виртуальное окружение;
устанавливает зависимости;
создаёт .env из переданных параметров;
создаёт systemd-сервис;
запускает сервис;
включает автозапуск.

Никакого ручного открытия файлов после загрузки на сервер не требуется.
